# 이슈 마무리

규칙은 `CLAUDE.md` 「커밋과 이슈」에 있다. 순서가 중요하다: **고증 파일 → push → 댓글 → 닫기 / 라벨**. 댓글의 링크는 push 된 main 의 파일과 커밋을 가리키기 때문이다.

- 저장소: `yonsei-reunion/campus-1997` (`gh` 는 저장소 루트에서 돌리면 알아서 찾는다)
- 라벨: `blocked`(새 자료 없이는 못 함), `현장 조사`(현장 · 학교 기록을 봐야 닫힘), `항공 사진`(원본 스캔으로 다시 볼 만함)
- `$S`: 스크래치 폴더. 댓글 초안은 `$S/comment_<번호>.md` 로 쓴다

## 순서

1. **이슈를 읽는다.** 본문과 댓글을 모두: `gh issue view <번호> --comments`. 마지막 댓글의 「남은 일」이 이번에 할 일의 목록이다.
2. **줄마다 끝을 정한다.** 남은 일의 줄마다 셋 가운데 하나:
   - (가) 게임에 옮김 / 결론 남 → 고증 파일에 근거 · 잰 값 · 잔차. 「남은 한계」 줄을 빼거나 줄인다
   - (다) 일부 좁혀짐 → 고증 파일에 적고 「남은 한계」 줄을 고친다
   - (나) 새 자료(1990년대 지상 사진 · 학교 기록 · 현장)가 있어야 함 → 「남은 한계」 줄에 이번에 찾아본 곳을 더한다
   「찾았지만 게임에 아직 안 옮김」으로 남은 줄이 있으면 마무리가 아니라 일이 남은 것이다.
3. **기록을 고증 파일로 옮긴다(push 전에).** 이슈 댓글에만 있는 잰 값 · 판단은 그 주제의 `reference/고증/<절>_<주제>.md` 로 옮긴다. 이슈 본문 · 댓글에는 값을 길게 두지 않는다.
4. **「남은 한계」 표의 이슈 칸을 고친다(같은 push 에).**
   ```bash
   grep -rn "issues/<번호>)" reference/고증/ reference/고증.md
   ```
   - 표는 `| 항목 | 게임 | 자료 | 이슈 |`, 이슈 칸은 `[#183](https://github.com/yonsei-reunion/campus-1997/issues/183)` 꼴이고 **열린 이슈만** 둔다.
   - 닫을 이슈의 번호가 있는 줄: 남은 일을 옮긴 열린 이슈의 번호로 바꾼다. 옮길 곳이 없으면 「—」. 줄 자체는 결론이 났을 때만 뺀다.
   - 줄을 빼면 `reference/고증.md` 「남은 한계」 목록의 항목 이름도 뺀다. 새 줄을 더했으면 목록에도 더한다.
   - 사람(캐릭터)에 대한 줄은 「남은 한계」에 두지 않는다. 표는 땅 · 건물 · 풍경이 자료와 맞는지만 다룬다.
   - 새 이슈를 만들 것이면(7번) 번호가 있어야 하니 **push 전에 먼저 만든다.**
5. **커밋하고 push 한다.** `shared-commit` 스킬. 커밋 메시지에 이슈 번호를 적지 않는다.
6. **댓글을 쓴다.** `$S/comment_<번호>.md`:
   - 맨 위: 이번에 무엇으로 무엇을 봤는지 한두 줄. 쓴 사진은 저장소의 파일로 링크한다.
   - **건물 · 장소마다 제목 하나**(`## 대강당 앞 돌계단 (게임에 옮김)`). 제목 끝의 괄호에 (게임에 옮김) · (일부 좁혀짐) · (새로 찾음, 옮기지 않음) 가운데 하나. 일의 종류(카메라 · 심기 · 문서)로 나누지 않는다. 한 곳에 속하지 않는 것은 맨 끝 `## 그 밖`.
   - 제목 아래: 바뀐 것 한 줄(「전 → 후」), 근거 한두 줄, `커밋: https://github.com/yonsei-reunion/campus-1997/commit/<해시>`, `기록: [고증 2.3.1](https://github.com/yonsei-reunion/campus-1997/blob/main/reference/고증/2.3.1_백양로의_단면.md) 「절 이름」`.
   - 잰 값을 길게 적지 않는다(표 금지에 가깝게). 숫자는 고증 파일에 있고 댓글은 그 절을 가리킨다.
   - 「사진 A」처럼 고증 안에서만 통하는 약칭은 나올 때마다 파일로 링크하고, 처음에 무엇인지 한 줄 적는다(사진 A = `reference/1997_백양로_항공사진.jpg`. 무엇을 찍은 사진인지는 `reference/고증/1_자료.md` 의 A 줄 그대로). 사진 링크는 한글 경로를 퍼센트로 바꾼다:
     ```bash
     python3 -c "import urllib.parse,sys;print('https://github.com/yonsei-reunion/campus-1997/blob/main/'+urllib.parse.quote(sys.argv[1]))" reference/1997_백양로_항공사진.jpg
     ```
   - `## 남은 일`: 줄마다 고증 파일 · 「남은 한계」 줄 이름을 링크하고, 무엇이 있으면 정해지는지(자료의 종류) 적는다. 마지막 줄에 「열어 둡니다」 또는 닫는 까닭.
   - 맨 끝: `새 소식: https://yonsei-1997.benelog.net/news.html?d=<날짜>` (그림이 있으면 `web/public/assets/news/` 의 파일 링크).
   - 에이전트의 초안을 쓸 때는 통합자에게 한 말(「닫아도 됨」, 「닫지 말고 … 권함」, 에이전트 이름)을 지우고 다시 쓴다.
   ```bash
   git fetch -q origin
   python3 .claude/skills/close-issue/check_comment.py $S/comment_<번호>.md     # 링크의 파일 · 「절 이름」 · 커밋이 origin/main 에 있는지
   gh issue comment <번호> --body-file $S/comment_<번호>.md
   ```
7. **닫을지, 열어 둘지, 새 이슈로 바꿀지.**
   - 다 했다 → `gh issue close <번호>` (댓글은 6번에서 이미 달았다). 4번에서 이슈 칸을 고쳤는지 다시 본다.
   - 일부만 했다 → 닫지 않는다. 「남은 일」이 댓글에 있으면 된다.
   - **진척이 없었다**(「남은 한계」에 새로 잰 값만 더했거나 아무것도 바뀌지 않음) → 긴 옛 이슈를 닫고 새 이슈로:
     1. 새 이슈를 만든다. 본문은 **조사할 것을 앞세운다**: 장소마다 `## 제목`, 줄마다 「정할 것 — 그것을 정해 줄 자료 · 찾을 곳 — 기록(고증 파일 · 「남은 한계」 줄 링크)」, 그 아래 「찾아본 곳」. 잰 값은 적지 않는다. 맨 위에 `#<옛 번호> 에서 옮김`.
        ```bash
        gh issue create --title "<곳>: <무엇으로 볼 것>" --body-file $S/new_issue.md --label "현장 조사"
        ```
     2. 옛 이슈 하나에 새 이슈 하나가 아니라, **정해 줄 자료나 장소로 묶는다**. 같은 건물을 다루는 열린 「현장 조사」 이슈가 이미 있으면 새로 만들지 않고 거기에 댓글로 항목을 더한다. 학교 기록으로 정해질 것은 #125(학교 기록)의 하위로 적는다.
     3. 「남은 한계」의 이슈 칸을 새 번호로 바꿔 push 한다(4번).
     4. 옛 이슈에 새 이슈를 링크한 댓글을 달고 닫는다.
   - `gh issue create` 가 권한 문제로 막히면 다시 시도하지 말고 사용자에게 알린다.
8. **`blocked` 라벨을 맞춘다.** 열어 둔 이슈마다 남은 일을 본다.
   - 남은 줄이 **모두** 새 자료(1990년대 지상 사진 · 학교 기록 · 현장) 대기 → `gh issue edit <번호> --add-label blocked`
   - 가진 자료로 할 수 있는 줄(원본 스캔 다시 읽기, 가진 사진의 카메라 풀이, 브라우저로 로드뷰 보기, 도면 다시 재기)이 **하나라도** 있다 → 달지 않는다. 붙어 있으면 `--remove-label blocked`
   - 새 자료를 찾았으면 뗀다. 현장 · 기록만이 닫을 수 있는 이슈는 `현장 조사` 라벨과 현장에서 볼 것의 목록(댓글)을 둔다.
9. **`next-session.md` 를 고쳐 쓴다**(저장소 루트, 추적하지 않는 파일). 남은 일만, 한 줄씩 이슈를 가리키게. 끝난 것의 기록이나 잰 값은 두지 않는다(기록은 이슈 댓글에 있다). 그 밖에 「알아둘 것」 몇 줄.

## 확인

- `gh issue view <번호> --json state,labels --jq '.state, [.labels[].name]'` 로 닫힘 · 라벨이 뜻대로인지
- `grep -rn "issues/<닫은 번호>)" reference/고증/` 가 「남은 한계」 표에서 비었는지(본문의 지난 기록에 남은 링크는 괜찮다)
- 댓글의 커밋 링크가 push 된 해시인지(`check_comment.py` 가 본다. push 전 해시나 rebase 로 바뀐 해시는 「없는 커밋」으로 나온다)

## 알려진 함정

- **push 전에 댓글을 달지 않는다.** 통합 브랜치에서 cherry-pick 한 커밋은 main 을 fast-forward 하면 해시가 그대로지만, rebase 하면 바뀐다.
- **고증의 기준이 바뀌면**(높이 기준 · 좌표 원점 · 다시 잰 값) 고증 파일의 값을 새 기준으로 고쳐 적는다. 「그 전 기록은 옛 기준」 같은 단서를 남기지 않는다. 옛 이슈 본문에 남은 수치는 지우고 파일을 가리키게 고친다(`gh issue edit <번호> --body-file`).
- **높이는 해발로** 적는다(댓글 · 이슈 · 고증 모두).
- 이슈 번호가 들어간 글은 이슈와 고증 파일에만. 커밋 메시지 · 새 소식에는 넣지 않는다.
- 여러 이슈를 한꺼번에 올릴 때는 초안을 모두 써서 `check_comment.py $S/comment_*.md` 로 한 번에 본 뒤 올린다.
