# 카카오 로드뷰 측정 (재창조 전 백양로)

공사 전 로드뷰(2008년 8월 · 2010년 12월 · 2011년 4월)에서 방위를 읽어, 바뀌지 않은 건물을 기준으로 파노라마 · 조형물 · 차도의 자리를 푸는 도구입니다. [#82](https://github.com/yonsei-reunion/campus-1997/issues/82)에서 썼습니다.

| 파일 | 하는 일 |
|---|---|
| `rv.mjs` | 헤드리스 로드뷰: `near` · `info` · `shots` · `past`(옛 파노라마를 비교 화면으로) |
| `osm_overlay.mjs` | 카카오 지도 · 스카이뷰에 OSM 외곽선을 겹쳐 그림 |
| `ruler.py` | 화면에서 화소 열을 읽는 자 달린 크롭(`crop`) · 쌓기(`stack`) · 모음(`sheet`) |
| `bearings.py` | 읽은 화소와 그 방위의 기록 |
| `resect.py` | 카카오 방위를 쓰지 않는 후방교회: 파노라마 · 독수리상 · 활천대 · 차도 |
| `statues.py` | 남쪽 파노라마 169 ~ 177 모두로 독수리상 · 활천대를 다시 풂(파노라마마다 작은 흔들림 `--jit`, 랜드마크 사전분포 `--lm`) |
| `groups.py` | 독수리상 「연세인」 네 무리의 자리와 독수리상 축 |
| `drum.py` | 백주년기념관 원통: 2011년 163 ~ 174의 원통 남서쪽 윤곽을 `statues.py` 판독과 함께 풂(`--c12 osm\|kakao\|drop`, `--south`, [#101](https://github.com/yonsei-reunion/campus-1997/issues/101)) |
| `north/` | s 267 ~ 385 m 차도: 2010 · 2011년 파노라마를 도서관 · 학생회관 · 백양관 · 백주년 모서리로 풂(`final.py` 파노라마마다, `joint.py` 주행마다 한 직선), 노란선으로 차 자리(`lanes2.py`). `LMSHIFT` 로 기준점을 옮겨 시험 |
| `eng/` | 2014 ~ 2015년 증축 전 제1공학관 남동 모서리: 측면 도로 · 백양로 파노라마의 묶음 조정(`net.py`, 판독 `readings.py`). 사진 A 카메라의 깊이를 묶는 기준점. 동쪽 면 북동 끝([#83](https://github.com/yonsei-reunion/campus-1997/issues/83)): `net.py --nface`(2011년 159 · 160, 길 방향 자리에 걸려 74.5 ~ 82.8 m), `pillars.py`(162 한 화면의 창 기둥 원근, 차로 거리에 걸려 79.5 ~ 83.9 m). 사진 A는 86.7 m(`reference/고증.md` 3.8). 현관 앞 진입로: `mouth.py`(2008 · 2011년 165, 노란선 소실점 · 기울기와 남동 모서리로 화단 띠 끊김 · 현관 · 볼라드 줄) |
| `pw.mjs` | playwright 찾기, 게임 좌표 ↔ 위경도 |

## 측정할 때

- **각도**: 뷰어는 화면 방향 각도의 소수점을 버립니다(258.3 · 258.6 · 258.9°가 모두 258°). `rv.mjs`는 정수 각도로 겨누고 그 값을 출력합니다.
  - 화소의 방위 = 각도 + atan((x − 694) / f)
  - f = 783 px(줌 3), 약 458 px(줌 0), 1388 × 900 화면 기준
  - 기울기는 0으로 둡니다. 그래야 세로 모서리가 곧게 보입니다
  - 그래도 수평선이 화면 가운데라고 보지 않습니다. 2011년 4월 차의 줌 0 화면은 노란선 소실점이 가운데보다 13 ~ 19 px(1.6 ~ 2.4°) 위였습니다
    (`north/lanes2.py`). 높이 · 내려다본 각을 잴 때는 같은 화면의 소실점으로 수평선 행을 정하거나, 한 면의 위아래처럼 같은 거리의 두 점 차이만 씁니다
  - 크기는 거리에 비례하므로 거리도 카카오 위치가 아니라 풀어 낸 자리로 셈합니다. 처음 독수리상 단 · 기둥은 카카오 위치에서 옛 자리까지 20.7 m로
    재서(실제 23.2 ~ 23.7 m) 13 % 작게 나왔습니다(`reference/고증.md` 4.1.1)
- **카카오 방위 · 위치 값을 믿지 않음**
  - 카카오 북쪽은 파노라마마다 최대 약 5° 틀립니다
  - 위치 값도 쓰지 않습니다. 2011년 노드는 도로 링크 위에 붙인 값이고(같은 방위 구간의 노드가 한 직선 위, rms 0.1 ~ 0.2 m), 2010년 12월 옛 파노라마는 그 2011년 노드 선 위로 옮겨 놓은 값입니다(43장이 평균 −0.07 m, sd 0.34 m). 실제 찍은 자리는 그 선에서 −3 ~ +1.8 m 떨어져 있습니다. 2008년 8월 것은 선보다 서쪽 1.6 ± 0.6 m에 따로 있습니다
  - 그래서 한 화면 안 두 대상 사이의 각만 쓰고, 파노라마마다 방위를 미지수로 풉니다(`resect.py`)
- **옛 파노라마**
  - 2010년 12월 백양로 id는 주소로도 `setPanoId`로도 열리지 않습니다. `rv.mjs past`가 날짜 슬라이더와 비교 화면으로 엽니다
  - 이때 카카오는 옛 파노라마의 자리로 지금 노드의 자리를 돌려줍니다. 실제로는 몇 m 떨어져 있으니 랜드마크로 자리를 풉니다(187 노드의 2010년 것은 기준점 넷으로 풀면 1.8 m 동쪽. 처음의 「약 6 m」는 각 하나와 2010년 화면의 도서관 북동 모서리 어긋남에서 나온 값)
  - 옛 파노라마의 저장 자리는 `rv.map.kakao.com/roadview-search/v2/node/<2011 노드>?SERVICE=glpano` 의 `street.past[]` 에 있습니다(옛 id로 물으면 빈 값)
  - 페이지가 panoid를 무시하고 다른 곳의 기본 로드뷰를 여는 때가 있습니다. 찍은 뒤 출력의 pano id와 날짜를 확인합니다
- **모서리 판독**
  - 도서관 남동 모서리에는 동남향 띠(약 12 px)가 있어 명암 경계가 아침 · 정오 화면에서 띠의 양끝을 가리킵니다(±0.45°)
  - 2010년 화면에서 길 방향보다 27° 넘게 왼쪽에 있는 모서리(도서관 북동 · 남서)가 0.6 ~ 1.6° 어긋나는 일이 있습니다(이음매로 추정)
  - 백주년기념관 북서 모서리(C12)는 OSM과 카카오 기본 지도가 3 ~ 4 m 다릅니다. 그것에 기대는 결과는 두 자리로 다 풀어 봅니다
  - 3배 크롭으로 읽습니다. 도서관 남쪽 면에도 아치가 있어 작은 화면에서는 동쪽 면과 헷갈립니다
  - 도서관 남쪽에는 2000년대 건물(학술정보원, 게임에는 없음)이 서 있습니다
  - 학생회관은 2011년에 나무와 공사 그물에 가렸습니다
  - 기준으로 쓴 OSM 외곽선(도서관, 제1공학관, 백주년기념관)은 스카이뷰 지붕과 1 m 안에서 겹칩니다(`osm_overlay.mjs`)
- **화면 캡처**: 저장소 밖(스크래치 폴더)에 쓰고 커밋하지 않습니다(CLAUDE.md 「고증 자료」). 출처에는 파노라마 id와 촬영 연월을 적습니다.

## 예

```sh
node tools/roadview/rv.mjs info 1017220175                     # 2011년 파노라마와 옛 파노라마 목록
node tools/roadview/rv.mjs shots spec.json /tmp/rv             # spec: [{"pano":1017220187,"look":[-85.4,-71.1],"zoom":3}]
node tools/roadview/rv.mjs past 1017220175 2010 /tmp/rv e:pan:282:3
python3 tools/roadview/ruler.py crop /tmp/rv/x.png /tmp/c.png 640 60 860 420 3
node tools/roadview/osm_overlay.mjs /tmp/ov.png -96 -26 1 sky   # 도서관 둘레 스카이뷰
uv run --with numpy --with scipy python tools/roadview/resect.py --past
uv run --with numpy --with scipy python tools/roadview/resect.py p187
```

`resect.py`의 모형(`--model`)은 셋입니다.
- `two`: 남쪽(169 ~ 175) · 북쪽(178 ~ 187) 묶음이 따로 이동
- `one`: 이동 하나
- `drift`: 이동이 길을 따라 선형으로 바뀜

`--drop 175:C12`처럼 판독을 하나씩 빼 볼 수 있습니다.

결과(2026-11-08, `reference/고증.md` 4.1.4 · 4.3):
- 독수리상: `resect.py` 서쪽 4.3 ± 0.5 m, `statues.py` 5.1 ± 0.9 m(처음 자리 (−66.5, −161.0)에서). 1994년 사진 · 사진 A와 합쳐 게임은 4.6 m
- 활천대: 독수리상보다 2.0 ± 0.6 m 덜 옮겨짐(`statues.py`), 게임은 2.5 m
- 독수리상 축: 194.7 ± 2.0°(`groups.py`), 게임 194°
- 첫 판독의 172 E(563.5)는 잘못 읽은 것이라 558.1로 고침

```sh
uv run --with numpy --with scipy python tools/roadview/statues.py --jit 0.5 --past 2010@175 --drop 2010@175:F --loo
uv run --with numpy --with scipy python tools/roadview/groups.py
```
